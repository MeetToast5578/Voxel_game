# Spec 9: Meter-based world scale and realistic trees

**Built by:** Claude. It touches the generator and worldgen.
**Depends on:** spec 2 (0.6 m blocks) and spec 6 (cubic chunks, 3D light). Lands before phase 2 (terrain).

## Goal

Blocks are 0.6 m, but only the player moves with that scale. The terrain, caves, trees, clouds and spawn search are still written in block counts, so the same world now has the same shape on a finer grid, with no extra detail.

This spec keeps every world size in meters and fills them with 0.6 m blocks. A mountain stays the same height in meters, and the sea stays at the same height in meters. Trees become realistic: an 8–12 m tree is 13–20 blocks tall, with a trunk, branches and an irregular crown.

## Current behaviour

- Only `src/config.ts`'s player and physics constants use `metersToBlocks`.
- `src/world/generator.ts` treats every number as blocks: height noise (`base * 14`, `hills * 6`, `m * m * 70`), noise wavelengths (256, 64, 512), cave scales (40, 24), sea level (40), soil depth (3), beach and cave bands (1, 3, 5), tree chance (0.012 per column), trees (4–6 blocks tall, a 5×5 crown).
- The legacy column is 128 blocks tall, which is 77 m after the scale change, and its terrain tops out at 116 blocks.
- Clouds (height, texel size, drift speed), spawn search (radius, step) and the surface band cap (`MAX_SURFACE_DISTANCE`) are in blocks.

## Requirements

### Config (`src/config.ts`)

1. Move the `// ---- Scale ----` section above the World section, so the block-derived constants below can use `metersToBlocks`.
2. Add terrain values in meters, with the old numbers kept as meters:
   - `SEA_LEVEL_M` = 40
   - `TERRAIN_MAX_M` = 116 (the old cap)
   - `LEGACY_HEIGHT_M` = 144
   - height noise: `BASE_WAVELENGTH_M` 256, `HILL_WAVELENGTH_M` 64, `MOUNTAIN_WAVELENGTH_M` 512; amplitudes `BASE_AMP_M` 14, `HILL_AMP_M` 6, `MOUNTAIN_AMP_M` 70
   - caves: `CAVE_SCALE_H_M` 40, `CAVE_SCALE_V_M` 24
   - soil: `SOIL_DEPTH_M` 1.8
   - shores: `BEACH_BAND_M` 1, `SHORE_CAVE_BAND_M` 3, `SHORE_ROOF_M` 5
3. Derive the block values from these with `metersToBlocks`, rounding to whole blocks:
   - `SEA_LEVEL` = round(40 / 0.6) = 67 (40.2 m)
   - `LEGACY_HEIGHT` = the smallest whole number of chunks at or above `LEGACY_HEIGHT_M`, which is 240 (15 chunks)
   - the other values follow the same rule
4. Tree values in meters: `TREE_HEIGHT_MIN_M` 8, `TREE_HEIGHT_MAX_M` 12, `TREE_REACH_M` 4.8 (the most a tree's blocks may sit from its trunk). `TREE_DENSITY_PER_M2` = 0.012, the old per-square-metre density. The per-column chance is `TREE_DENSITY_PER_M2 * BLOCK_SIZE_M²`, so tree density per square metre is unchanged.
5. Clouds in meters: `CLOUD_HEIGHT_M` 100, `CLOUD_TEXEL_M` 12, `CLOUD_PLANE_M` 768, `CLOUD_DRIFT_M_S` 1.5. `src/render/clouds.ts` imports them.
6. `SURFACE_MAX_DISTANCE_M` = 2000 (the old `MAX_SURFACE_DISTANCE`), in meters, converted for the chunk manager.
7. Spawn search: `SPAWN_RADIUS_M` = 512 and `SPAWN_STEP_M` = 8. The step is rounded to whole blocks. The ring search needs the step to divide the radius, which it always does, since the radius is a whole number of steps.

### Terrain (`src/world/generator.ts`)

8. Noise is sampled in meters. A block at world x is sampled at `x * BLOCK_SIZE_M`. Terrain, cave noise and the beach test use this rule, so every feature covers the same area in meters as before.
9. The height in meters is `SEA_LEVEL_M + 2 + base * BASE_AMP_M + hills * HILL_AMP_M + m² * MOUNTAIN_AMP_M`. It converts to blocks with `metersToBlocks`, is floored, and is clamped to `[1, metersToBlocks(TERRAIN_MAX_M)]`.
10. The legacy column is `LEGACY_HEIGHT` blocks tall (240). Chunk slices, the stone floor at y = 0 and the air above the column stay as in spec 5, with the new height. Trees and caves are identical in every chunk slice.
11. A column's height cache. `heightAt` caches each column's 16×16 heights in a map keyed by `cx,cz`, so a tree's neighbour columns are not recomputed. The map is cleared when it passes 4,096 entries. The cache must give the same result as recomputing.
12. `getHeight` keeps its meaning and stays the public height function for spawn.

### Trees (`src/world/trees.ts`, new, pure)

13. Trees are generated by a pure function of `(seed, anchor)`. The output does not depend on which chunk asks for it.
14. A tree's blocks are computed in full, then written only where they fall in the chunk being filled. This keeps chunks seamless when a tree crosses a border.
15. Anchors are columns whose ground is grass: not beach, and not carved by a cave at the surface. A chunk checks every anchor within `TREE_REACH` blocks of its columns, so a crown that reaches into a neighbour's chunk is placed by both.
16. Shape rules, in meters and converted to blocks:
    - Total height is random in [8, 12] m: 13–20 blocks.
    - A 1-block-wide trunk (0.6 m) from the ground up to the top of the bare trunk, at 45–60% of the height.
    - 4–6 branches leave the trunk at random angles. Each is a short run of 2–4 horizontal log steps, rising gently, with one step at a time along X or Z so every log touches the one before it. Each ends in a small leaf cluster.
    - The main crown is a noisy ellipsoid with a horizontal radius of 3–3.6 m (5–6 blocks). It runs from the top of the bare trunk to the top of the tree, so the trunk top is always under leaves. Each leaf cell is included or excluded with a small random jitter, so the edge is ragged.
    - Leaves fill only air. Logs replace whatever is in their cell, as before.
17. Every tree stays within `TREE_REACH_M` (4.8 m, 8 blocks) of its trunk horizontally, and within `MAX_TREE_RISE` of its ground block vertically. Both bounds are tested.
18. The ground block under the trunk becomes dirt, as before.
19. Density: `TREE_DENSITY_PER_M2` gives the same count of trees per square metre as before.

### Shores and soil

20. The beach test is `h - SEA_LEVEL <= BEACH_BAND`, with the band in blocks. The cave roof under water or beach is `SHORE_ROOF` deep, and caves are not carved within `SHORE_CAVE_BAND` of the sea.
21. Soil is `SOIL_DEPTH` blocks of dirt under the grass (1.8 m rounds to 3 blocks).

### Clouds, spawn and chunk manager

22. `src/render/clouds.ts` takes its sizes from config, converted with `metersToBlocks`.
23. `src/world/spawn.ts` searches in meters, converted to blocks. Its surface check uses the beach band.
24. `src/world/chunkManager.ts` takes `SURFACE_MAX_DISTANCE` from config.

### Unchanged (on purpose)

25. Render distance stays in chunks. The default of 8 chunks is now 77 m (8 × 9.6 m), down from 128 m before the 0.6 m scale. The PR states this, because it is a visible change that the owner may want to undo by raising the default.
26. Light reach stays at 14 blocks. It is a grid effect that the mesher's exactness argument depends on. Light reach in meters falls to 8.4 m, which the PR states.
27. `STEP_HEIGHT` stays at 1 block (0.6 m) and is not changed.
28. Chunk size stays at 16 blocks.

### Docs

29. `README.md`: one line under the scale line: "Trees are 8–12 m tall." Scale and sea level in meters are not added to the README.
30. `docs/ROADMAP.md`: a "Phase 1b: meter-based world scale" entry before Phase 2. `docs/specs/README.md`: a row for spec 9.

## Out of scope

- Terrain redesign (climate, rivers, geology): phase 2.
- Any external art or the addon's files. Textures stay procedural.
- A new save format. Saves store block states by name, so they are unaffected.
- Mesh, light and streaming code, except where they read the constants above.

## Acceptance criteria

- `npm run check` passes.
- `npm run smoke` passes in CI or a cloud session.
- Every test that encoded the old block counts is ported with the same intent, and the PR lists each change with the old and new value.
- Measured in the PR: a mature tree in the F3 overlay (8–12 m), chunks per square kilometre before and after, and mesh time per surface chunk against the 3 ms target.
- Manual check with `npm run dev`: a forest looks more detailed at the same world size, and sea level is at about 40 m.

## Test cases

1. **Conversion.** `SEA_LEVEL` is 67, `LEGACY_HEIGHT` is 240 and `LEGACY_CHUNKS` is 15. Meter values convert with `metersToBlocks`.
2. **Terrain in meters.** Over a 512×512 m area for seed 42, the highest surface is at most 116 m, the lowest land is above sea level for at least some columns, and the tops match a brute-force scan.
3. **Legacy slices.** Chunks `cy` 0..`LEGACY_CHUNKS` − 1 stacked equal the legacy column; `cy` = `LEGACY_CHUNKS` is all air; `cy` −3 is all stone.
4. **Tree shape.** For a grid of anchors, each tree's top is 12–20 blocks above its ground (the crown's top cell can be dropped by the jitter, so 12 is the floor), its blocks stay within `TREE_REACH` (8 blocks) horizontally of the trunk, and within `MAX_TREE_RISE` of the ground. Every log is connected to the trunk through logs. The cell above each trunk top is a leaf.
5. **Determinism.** The same `(seed, anchor)` gives the same tree on every call, and a tree split across two chunks gives the same blocks as the same tree placed in one chunk.
6. **Border trees.** For seed 42 over a patch of columns, every log of every placed tree appears in the generated world at its position, including trees whose crown crosses a column border, and both sides of such a tree are drawn.
7. **Density.** Over a 200 × 200 block patch (about 0.014 km²) of seed 42, the anchor count per square metre is within 20% of `TREE_DENSITY_PER_M2`.
8. **Shores.** No tree grows on a beach. No cave is carved within the shore band.
9. **Spawn.** `findSpawnColumn` returns a dry column within the search radius in meters.
10. **Chunk manager.** The surface cap is `SURFACE_MAX_DISTANCE`.
11. **Ported tests.** `tests/trees.test.ts`, `tests/generator.test.ts`, `tests/caves.test.ts`, `tests/spawn.test.ts`, `tests/support/stackedColumn.ts`, `tests/debugText.test.ts` and `tests/config.test.ts` keep their intent with the new numbers.
