# Spec 1: CI

## Goal

Every pull request, and every push to `main`, runs the same checks a contributor runs locally: `npm run check` and `npm run smoke`.

## Requirements

1. Add one GitHub Actions workflow file, `.github/workflows/ci.yml`.
2. Triggers:
   - pushes to `main`
   - pull requests (any target branch)
   - manual runs (`workflow_dispatch`)
3. Two separate jobs on `ubuntu-latest`, named `check` and `smoke`, so a failure shows which part broke. They run in parallel.
4. Steps both jobs share:
   - Check out the repository.
   - Set up Node 22 with npm caching. Node 22 matches the dev environment, and Node 20 is end-of-life.
   - Install with `npm ci`. Never `npm install`, and never upgrade anything.
5. The `check` job runs `npm run check`.
6. The `smoke` job:
   - Installs Playwright's Chromium and its system libraries with the repo's pinned Playwright (`npx playwright install --with-deps chromium`).
   - Then runs `npm run smoke`.
   - Does not set `CHROMIUM_PATH`.
7. The `smoke` job always uploads the `screenshots/` folder as an artifact, whether it passed or failed. Keep it for 7 days. A missing folder warns rather than failing the step.
8. Set the workflow permissions to read-only repository contents (`contents: read`).
9. Add a concurrency group per workflow and ref that cancels an older, still-running run when a newer commit arrives.
10. Give each job a 15-minute timeout.
11. In `README.md` under **Development**, add one sentence saying CI runs `npm run check` and `npm run smoke` on every pull request and every push to `main`.

## Out of scope

- Deploying or publishing anything
- A matrix of Node versions or operating systems
- Caching Playwright browsers
- A status badge (optional; add one only if it's trivial)

## Acceptance criteria

- The pull request that adds the workflow shows two checks, `check` and `smoke`, and both are green.
- The `smoke` job log shows a `check passed:` line for every smoke check, followed by `SMOKE TEST PASSED`.
- The run has a downloadable artifact containing `smoke.png`, `look.png`, `menu.png` and the other screenshots.
- `package.json` and `package-lock.json` are unchanged.
- No step uses `continue-on-error`, `|| true`, or anything else that hides a failure.

## Test cases

1. **Green run.** Open the pull request and confirm both jobs pass.
2. **Repeatability.** Re-run the `smoke` job once from the Actions page and confirm it passes again.
   - If it fails on CI but passes locally, or fails only sometimes, report it with the log.
   - Do not add retries, longer timeouts or weaker assertions to make it pass.
3. **Failure is visible (review only, no push needed).** Read the workflow and confirm that a failing command fails its job. GitHub's default shell already does this.
4. **Artifact.** Download the screenshots artifact from the run and confirm the images show the game, not a blank or black canvas.
